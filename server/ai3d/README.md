# AI 3D-модель товара по одному фото (TripoSR, без платных API)

Продавец нажимает в кабинете «Создать 3D с помощью AI». Сервер ставит задачу в очередь. Этот обработчик забирает задачу,
строит настоящую 3D-сетку по фото открытой нейросетью **TripoSR** (лицензия MIT, github.com/VAST-AI-Research/TripoSR) и
возвращает файл `.glb`. Продавец крутит модель и решает: «Сохранить 3D», «Повторить» или «Удалить 3D». Покупатели видят
переключатель «Фото / 3D» только после «Сохранить 3D». Оригинальное фото не трогается никогда.

```
кабинет продавца ──POST /model3d──► API (очередь m3d_jobs) ◄──HTTPS, токен── worker.py (Mac / сервер)
                                        │                                 фото → rembg → TripoSR → сетка → GLB
покупатель ◄── карточка «Фото / 3D» ◄───┘ (только опубликованные модели)
```

Обработчик сам **забирает** задачи по HTTPS с секретным токеном. Ему не нужен белый IP и открытые порты. Его можно перенести
с Mac на отдельный сервер без изменений в сайте: на сервере меняется только место, где запущен `worker.py`.

## Что нужно

- Mac с Apple Silicon (M1–M4). Для M4 с 16 ГБ памяти хватает: TripoSR на вывод занимает около 6 ГБ.
  Работает через MPS (графика Apple), неподдерживаемые операции сами уходят на CPU.
- Python 3.10 или 3.11 (`brew install python@3.11`) и git (`xcode-select --install`).
- Около 4 ГБ на диске (PyTorch, веса модели ~1,7 ГБ, модель удаления фона ~170 МБ). Веса скачиваются один раз, при первом
  запуске, с Hugging Face.

## Запуск на MacBook

1. На сервере в `server/.env` задайте длинный случайный токен и перезапустите сервер (`imorat restart` или `systemctl restart imorat`):
   ```
   MODEL3D_WORKER_TOKEN=<openssl rand -hex 32>
   ```
   Без токена функция выключена. На сайте нет кнопки, сервер отвечает `model3d_off`.
2. На Mac, в папке проекта:
   ```
   cd server/ai3d
   bash setup_mac.sh
   ```
   Скрипт создаёт `venv` рядом с собой, ставит PyTorch, TripoSR на зафиксированном коммите и пакеты, проверяет MPS.
   Он создаёт файл `~/.qurilish-ai3d.env`. Впишите в него адрес API и тот же токен:
   ```
   AI3D_SERVER=https://api.ваш-домен.uz
   MODEL3D_WORKER_TOKEN=<тот же токен>
   ```
3. Проверка связи: `bash run_mac.sh --check`. Ответ должен быть `server …: N pending job(s)`.
4. Запуск: `bash run_mac.sh`. При первом запуске скачиваются веса, это несколько минут. Дальше в журнале видно каждую задачу:
   `job 12: product 345 …` → `mesh … faces, GLB 2.1 MB` → `job 12 done in … s`.
5. Чтобы обработчик работал в фоне и сам запускался после входа в систему: `bash setup_mac.sh --autostart`.
   Журнал: `~/Library/Logs/qurilish-ai3d.log`.

Если не хватает памяти, уменьшите нагрузку: `AI3D_CHUNK=4096` и `AI3D_MC_RESOLUTION=192` в `~/.qurilish-ai3d.env`.
Можно и полностью уйти на CPU: `AI3D_DEVICE=cpu`, это медленнее.

## Как проверить генерацию в Quriliş Go

1. Войдите как продавец. Раздел «Товары»: добавьте товар с фото или возьмите свой товар с фото.
2. Нажмите «Создать 3D с помощью AI». Откроется окно: слева оригинальное фото, справа настоящий статус.
   - «В очереди», если обработчик не запущен. Окно так и пишет: «AI-обработчик сейчас не в сети».
   - «AI строит 3D-модель…», когда обработчик взял задачу.
3. Когда модель готова, справа появится 3D: покрутите её мышью или пальцем, приблизьте колесом или двумя пальцами.
   «Сохранить 3D» открывает её покупателям, «Повторить» делает заново, «Удалить 3D» удаляет модель (фото остаётся).
4. Откройте товар как покупатель. Внизу фото есть переключатель «Фото / 3D».

Модель также можно сохранить себе для проверки: `bash run_mac.sh --once --keep ~/Desktop/models`. Готовый `.glb` открывается
в «Просмотре» на Mac.

## Что делает обработчик с каждой задачей (`worker.py`, `meshkit.py`)

1. Скачивает оригинальное фото задачи (`GET /api/worker/model3d/:id/photo`).
2. Поворачивает фото по EXIF и уменьшает до 1024 px.
3. Удаляет фон (rembg). Если на фото не нашлось предмета, задача завершается ошибкой `bad_image`, продавец видит причину.
4. Центрирует предмет (85 % кадра) на сером фоне, как ждёт TripoSR.
5. Делает вывод TripoSR (MPS, CPU или CUDA). Если на GPU не хватило памяти или он не справился, эта задача досчитывается
   на CPU, а следующая снова идёт на GPU. Если поверхность не найдена, это ошибка `bad_image`, без повторов.
6. Строит сетку методом marching cubes, 256³, с цветами вершин из модели. На Mac без `torchmcubes` работает замена на
   PyMCubes или scikit-image.
7. Убирает мелкие оторванные кусочки. Упрощает сетку до `AI3D_MAX_FACES` граней (fast-simplification), а цвета новых
   вершин снова спрашивает у модели.
8. Поворачивает модель в систему glTF (Y вверх), ставит её на пол, по центру. Считает нормали и переводит цвета в линейное
   пространство.
9. Пишет GLB: только ядро glTF 2.0, без расширений, около 20 байт на грань. Обычно это 1–3 МБ.
10. Отправляет файл (`POST /api/worker/model3d/:id/result`). Сервер ещё раз проверяет GLB и повреждённый файл не сохраняет.
11. При ошибке сообщает о ней (`/fail`). Временные ошибки сервер возвращает в очередь, до 3 попыток: нехватка памяти, сбой
    сети, ответы 5xx и 429. Битое фото или пустой результат в очередь не возвращаются. Временные файлы библиотек на время задачи
    лежат в отдельной папке, она удаляется всегда.

Сервер (`server/src/model3d.js`) ведёт очередь: статусы `pending → processing → completed | failed`.
- У товара одна активная задача; повторный запрос на то же фото не создаёт вторую.
- Задачу, которую обработчик бросил больше чем на 20 минут, сервер возвращает в очередь.
- Новое фото отменяет незаконченную задачу и убирает старую модель.
- Продавец может менять только свои товары.
- Лимит на магазин в день: `MODEL3D_PER_STORE_DAY`. Предел очереди: `MODEL3D_MAX_QUEUE`.
- Модель генерируется один раз и хранится в `uploads`. При каждом открытии товара заново ничего не генерируется.

## Ограничения

- TripoSR восстанавливает предмет по одному снимку. Невидимые стороны он **достраивает примерно**, мелкий текст и логотипы
  получаются размытыми. Поэтому модель никогда не публикуется сама: продавец сначала её проверяет. Покупатель видит пометку
  «Модель создана AI по одному фото — скрытые стороны примерные». Размеры из модели нигде не берутся.
- Лучше всего получаются цельные предметы на однотонном фоне: мешки, вёдра, коробки, инструмент, смесители. Хуже всего —
  прозрачные, зеркальные и очень тонкие предметы, а также наборы из многих частей.

## Тесты

- `python3 -m unittest discover -s server/ai3d/tests` — сетка, оси, нормали, цвета и запись GLB (нужны numpy и scikit-image).
- `node --test server/test/api.test.mjs`:
  - очередь и проверки сервера;
  - тест «the Python AI 3D worker…» запускает настоящий цикл `worker.py` против сервера. Вместо TripoSR там тестовый движок
    `tests/worker_live.py`: цветной брусок, не AI. Он проверяет только очередь, загрузку и сообщения об ошибках.

## Стоимость

Программы бесплатные и открытые: TripoSR (MIT), PyTorch, rembg, Three.js (MIT, просмотрщик на сайте). Плата за генерацию не
берётся, ключи платных сервисов не нужны. Но сама работа стоит ресурсов:
- **электричество и время Mac**: обработчик работает, только пока Mac включён и не спит;
- **сервер API и хранение моделей** (`uploads`, 1–3 МБ на модель): обычный VPS, то есть платная инфраструктура;
- для круглосуточной работы без Mac нужен отдельный компьютер или сервер с GPU (дешевле всего — свой компьютер с NVIDIA)
  или постоянно включённый Mac mini. На сервере без GPU TripoSR тоже работает, на CPU, но медленно: минуты на модель.
