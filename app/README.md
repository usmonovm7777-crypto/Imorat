# Приложение Imorat Go (Android и iPhone)

Приложение собирается **из того же сайта** с помощью Capacitor 8: один код, одинаковый каталог, корзина,
заказы, кабинет продавца и Usta AI. Внутри приложения добавлены нативные части: push-уведомления о заказах,
возврат из банка по ссылке `imoratgo://`, кнопка «Назад» на Android, настройки камеры/фото/геолокации для iOS.

## Честное состояние (1 ноября 2026)

| Часть | Состояние | Чем проверено |

| Подписанный AAB для Google Play | конвейер готов (`Actions → Android app → release`), **ключ подписи и аккаунт Play Console ещё не созданы** | запуск без секретов останавливается с понятной ошибкой |
| Проект iOS | создаётся из сайта, разрешения и privacy-манифест добавляются скриптом; **компилируется на macOS-раннере GitHub без подписи** | `Actions → iOS app (build check)` |

| Push в приложении | сервер отправляет через FCM (Android) и APNs (iPhone), приложение регистрирует токен и открывает нужный заказ по нажатию; **ключи Firebase и APNs ещё не получены**, поэтому в реальности не отправлялось | автотесты сервера с поддельными FCM/APNs |

Пока эти пункты не закрыты, называть приложение «готовым к публикации» нельзя.

## Режимы

- **Рабочий режим** — в сборку передан адрес сервера (`IMORAT_API`, переменная репозитория или `../config.js`). Все заказы,
  оплата и вход идут через сервер; при сбое связи приложение показывает ошибку и ничего не «изображает».
- **Демо** — адрес сервера пуст: данные живут только на устройстве, в шапке горит метка «демо». Демо допускается
  только в тестовых сборках; `npm run www:release` и магазинный конвейер **отказываются собирать** без HTTPS-адреса сервера.

## Три способа поставить Imorat Go на телефон

| Способ | Как | Когда |
|---|---|---|
| **Приложение из сайта (PWA)** | Открыть сайт → ☰ → «Приложение Imorat Go» → «Установить» (iPhone: «Поделиться» → «На экран Домой») | Уже сейчас, бесплатно; уведомления о заказах есть |
| **Тестовый APK** | GitHub → Releases → **app-latest** → `Imorat.apk` → установить (разрешить установку из этого источника) | После каждого обновления сайта |
| **Google Play / App Store** | см. разделы ниже | После аккаунтов разработчика и ключей |

## Сборка у себя

```bash
cd app && npm install
npm run android          # сайт → www/, cap sync, патчи, Android Studio
npm run ios              # только на Mac: сайт → www/, cap sync, патчи, Xcode
```
`IMORAT_API=https://api.imorat.uz npm run www:release` — магазинная сборка www/ (откажется без HTTPS-адреса).

Скрипты в `scripts/`: `prepare-www.mjs` (копия сайта + `config.js` только из публичных настроек),
`patch-android.mjs` (версия, подпись, `imoratgo://`, разрешение на уведомления, `google-services.json`),
`patch-ios.mjs` (Info.plist, `PrivacyInfo.xcprivacy`, entitlements), `make-keystore.sh` (ключ подписи, один раз).
Версия приложения — `version.json`: перед каждой загрузкой в магазин увеличивайте `versionCode`.

## Google Play — что сделать владельцу

1. Аккаунт Google Play Console (разово $25). Для личных аккаунтов, созданных после 13.11.2023, Google требует
   **закрытое тестирование: 12 тестировщиков непрерывно 14 дней**, и только потом открывает доступ к публикации.
2. Ключ подписи: на своём компьютере `bash app/scripts/make-keystore.sh` → четыре секрета в GitHub
   (`ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`). Файл `.jks`
   хранить в менеджере паролей; в репозиторий он не попадает (`.gitignore`).
3. Переменная репозитория `IMORAT_API` = адрес сервера (и `IMORAT_SITE_URL`, `IMORAT_YMAPS_KEY` при наличии).
4. Push: проект Firebase → добавить Android-приложение `uz.imorat.app` → `google-services.json` → секрет
   `GOOGLE_SERVICES_JSON`; на сервере — сервисный аккаунт (`FCM_SERVICE_ACCOUNT_FILE` в `.env`).
5. `Actions → Android app → Run workflow → release` → скачать артефакт `app-release.aab` → Play Console.
6. Карточка: описание, скриншоты, политика конфиденциальности `https://imorat.uz/legal/privacy.html`,
   ссылка на удаление аккаунта `https://imorat.uz/legal/delete-account.html`, форма Data safety (данные — как в политике),
   тестовый аккаунт для проверяющих (`REVIEW_ACCOUNTS` на сервере: номер и фиксированный код).
7. Требование Google с 31.08.2026: новые приложения — `targetSdk 36` (Capacitor 8 так и собирает; проверяется в логе сборки).

## App Store — что сделать владельцу

1. Apple Developer Program ($99/год) — на юрлицо нужен D-U-N-S номер.
2. Mac с Xcode 26 (с 28.04.2026 Apple принимает только сборки Xcode 26 / iOS 26 SDK). `npm run ios` → в Xcode:
   Signing & Capabilities → команда, **+ Push Notifications**; Product → Archive → TestFlight.
3. APNs-ключ (.p8) из Apple Developer → на сервер (`APNS_KEY_FILE`, `APNS_KEY_ID`, `APNS_TEAM_ID`, `APNS_ENV`).
4. App Store Connect: описание, скриншоты iPhone, App Privacy (как в `PrivacyInfo.xcprivacy` и политике),
   ссылка на политику, возрастной рейтинг, тестовый аккаунт для проверки (номер + код из `REVIEW_ACCOUNTS`).
5. Вход: для App Store вход по SMS должен работать по-настоящему (Eskiz) — проверяющие Apple не смогут войти через
   Telegram-бота. Google/Apple-вход в приложении не показывается, поэтому «Sign in with Apple» не требуется
   (правило 4.8 действует, когда предлагается сторонний вход); если Telegram-вход останется в приложении,
   юрист/ревью могут потребовать добавить Sign in with Apple — сервер его уже поддерживает (`APPLE_CLIENT_ID`).
6. Риск правила 4.2 «минимальная функциональность»: Apple отклоняет приложения, которые лишь повторяют сайт.
   В приложении есть нативные push, возврат из банка и камера, но решение остаётся за ревью — закладывайте одну-две итерации.

## Что проверить на реальных телефонах перед отправкой

- вход по SMS и через Telegram, выход, удаление аккаунта (Профиль → «Удалить аккаунт»);
- заказ из двух магазинов, оплата картой: переход в Payme/Click, возврат в приложение, статус «оплачен»;
- push: разрешение, приход уведомления о статусе, открытие нужного заказа по нажатию (в фоне и при закрытом приложении);
- кнопка «Назад» на Android (закрывает панели, потом главная, потом сворачивает), клавиатура в формах, шапка под
  статус-баром на Android 15/16 (edge-to-edge) и iPhone с «чёлкой»;
- кабинет продавца: принять заказ, фото товара камерой, вывод денег;
- работа без сети: понятная ошибка, корзина и форма не теряются.
